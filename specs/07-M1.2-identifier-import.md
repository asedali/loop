# M1.2 — Identifier import (ORCID / DOI / arXiv)

**Plan ref:** none available. The adoption plan itself is not in this repository;
`specs/06-M1.1-file-upload.md` refers to it and forward-references an **M1.3
`materials` table**, so this is the sibling slice that completes the M1
zero-friction-input theme. Defined here rather than recovered.

**Attacks:** gap 3 and the funnel, second half. M1.1 removed "find a text file on
disk"; this removes "go and find the paper and copy the abstract out of it". For a
researcher the most common handle on their own work is an identifier, not a file.

## Problem

After M1.1 a researcher can upload a PDF. That still requires having the PDF, at
the right version, with the right pages. The things a researcher actually has
to hand are identifiers: an ORCID iD on their CV, a DOI on a paper they wrote, an
arXiv ID on a preprint. Each is a pointer to public metadata, and each currently
means opening a browser tab, reading the abstract, and pasting it — with the
title truncated by the page layout, half the author list, and no way to get the
rest of their own publication list.

## Change

`POST /phase1/import` takes one identifier, fetches the public record, and returns
it as **editable Phase 1 material**. Submitting that material is an ordinary
`POST /phase1/extract`.

| Identifier | Provider | Endpoint | Material produced |
|---|---|---|---|
| `0000-0002-1825-0097` | ORCID | `pub.orcid.org/v3.0/{id}/record` | the work list — title, year, venue per work |
| `10.1000/xyz123` | Crossref | `api.crossref.org/works/{doi}` | title, authors, year, venue, abstract |
| `2301.01234`, `hep-th/9901001` | arXiv | `export.arxiv.org/api/query?id_list=…` | title, authors, date, DOI, abstract |

An ORCID iD is a **person**, not a work, so its material is a list of titles —
which is what Phase 1 actually consumes, since the titles are the claims. That
list is capped by `IMPORT_MAX_WORKS` (25) so a prolific researcher does not turn
one identifier into a 400 KB prompt, and the user is told when it was capped.

### Same round-trip as the upload, deliberately

Import produces *text into the Phase 1 textarea*, which is the same shape M1.1
established. Consequences, all of them wanted:

- **No new AI-call path.** No quota change, no new prompt, no new `llm_calls` row.
  An import cannot spend the user's budget, and the test suite asserts that.
- **Untrusted data, unchanged.** Fetched metadata is third-party text that may well
  contain instructions, and it reaches `llm.extract_ideas` through the same
  `--- BEGIN RESEARCHER MATERIAL (untrusted data) ---` wrapper as a paste. Passing
  through our own server earns it nothing.
- **The preview is the review.** The banner tells the user this is someone else's
  text and to read it before extracting.

### SSRF: the user never builds a URL

The design rule is that no amount of user input can reach anything but a path
segment on one of three hardcoded hosts. Four things together, and the last two are
load-bearing:

1. Patterns are anchored to the **whole string**, matched with `.match` rather than
   `.search`. A searchable pattern would accept a URL carrying a payload in its
   query string — the exact shape being avoided.
2. Only the single captured group is used; the rest of the input is discarded.
3. **Percent-encoding is the gate.** `quote(identifier, safe="")` can only emit
   unreserved characters and `%XX`, so by construction nothing survives that could
   change the request: no `/` (no extra path segment, no traversal), no `:` (no
   port or scheme change), no `@` (no userinfo), no `?`, no `#`, no whitespace.
   A character whitelist would have been **both weaker and wrong** — DOIs
   legitimately contain most of printable ASCII, so it would reject valid input
   while still depending on the pattern staying tight.
4. **Redirects are not followed.** A 302 from an allowlisted host to
   `169.254.169.254` is the whole attack; refusing to follow redirects removes it
   without needing to inspect a `Location` header or resolve a name.

Tested adversarially rather than by inspection: seven URL-shaped inputs must be
refused with *no socket opened*, and three DOIs carrying a live payload are
asserted to produce a URL whose payload is inert by construction.

### The import surface

| Risk | Control |
|---|---|
| SSRF / host control | Whole-string anchored pattern, single capture group, percent-encoded into a hardcoded URL, `follow_redirects=False` |
| Worker held open by a slow third party | `IMPORT_TIMEOUT_SECONDS` (10) on every request |
| Huge or endless response body | `IMPORT_MAX_RESPONSE_BYTES` (1 MB), enforced **while streaming**, not from `Content-Length` |
| Request flood | Own token bucket, `IMPORT_RATE_LIMIT_PER_MIN` / `..._IP_PER_MIN`, checked **before** the fetch so a refused import never touches a third party |
| Cross-user bucket interference | Separate `prefix` in `ratelimit.check`, so import capacity and LLM capacity cannot spend each other |
| Process memory growth | Cache bounded at `_MAX_CACHE`, same reasoning as `ratelimit._MAX_BUCKETS` |
| XML entity expansion (arXiv) | Response capped before parsing; `ElementTree` does not resolve external entities and raises on undefined ones |
| XML entity expansion (Crossref JATS) | Tags handled by regex, **not** by `ElementTree` — so the parser that would have to defend against it is never used |
| Confused deputy via a shared cache | Keyed on `(provider, identifier)`, not on user. The content is public bibliographic metadata; caching it globally is the point, and it is what keeps the app from hammering volunteer-run services |
| Unhelpful failures | Every failure — 404, 429, 5xx, timeout, DNS, unreadable body — becomes a sentence the user can act on. No status code, exception class, or URL is ever rendered |

### Not included

- **No LinkedIn, X, Google Scholar or Semantic Scholar.** Those need auth and are
  the fragile ones; the three here are open, stable, and unauthenticated.
- **No caching to disk or the database.** In memory only, TTL 24h. A missed hit
  costs one GET; a persisted cache would add a table, an account-deletion question,
  and a privacy surface for no user-visible gain.
- **No abstract from a DOI that has none.** The material says so explicitly rather
  than presenting a title-only record as if it were complete.
- **No batch import.** One identifier per request, so the rate limit and the
  preview are both per-thing.

Residual risk, stated rather than hidden: the three hosts are hardcoded but they
are third-party services, and if one is compromised or returns adversarial
content, that content reaches the preview. The untrusted-data wrapper is what
bounds the consequence — it is data to the model, never instructions.

## Tests

53 new. `httpx.Client` is replaced with a recorder, so the real `_get` runs —
status handling, the streaming cap, the timeout paths and the
`follow_redirects=False` are all exercised without a network.

- `TestSourceRecognition` — every accepted form, provider chosen by shape not by
  guessing, seven SSRF shapes refused with no socket opened, payloads encoded into
  an inert path segment, and the reachable host set asserted to be exactly three.
- `TestSourceFetching` — each provider's happy path, JATS tags and numeric
  character references decoded *before* tags are stripped (so `&lt;em&gt;` does not
  survive as live markup), arXiv's "Error" entry treated as a miss, ORCID's
  work-list cap, and every upstream failure turned into a sentence.
- `TestSourceCache` — repeat import costs no request, DOI case-insensitivity,
  per-identifier separation, TTL 0 disables it, and the map stays bounded.
- `TestImportRoute` — preview before any model call, extract is an ordinary Phase 1
  call, **import spends no monthly quota**, requires a login, hides itself and
  refuses when disabled, is throttled without contacting the source, and does not
  spend the LLM budget.
