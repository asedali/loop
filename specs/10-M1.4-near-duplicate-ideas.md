# M1.4 — "Also extracted as": near-duplicate idea cards, and a way to dismiss one

**Plan ref:** none available. The adoption plan is not in this repository. This
closes the idea-deduplication item in `docs/FLOW.md` §9.
**Attacks:** the funnel. Phase 1 works, and then the dashboard fills with six
cards that are the same idea wearing different words.

## Problem

Every extraction creates new cards, and the model is consistent enough to be
annoying about it. Two overlapping pastes produce "Sell sensors to hospitals" and
"Selling sensors to hospitals", and the researcher picks one without being told
the other exists. Nothing is lost — the cards are all still there — but the
dashboard stops being a decision and becomes a chore, which is the point where
people stop using it.

There is a second, quieter problem behind it. `IDEA_STATUSES` contains
`"rejected"`, the schema has a CHECK constraint for it, and **nothing in the app
ever writes it and no page offers it**. So there is no way to say "not this one" —
the only way to retire an idea card is to select it into a venture. The enum has
been half-built since M0.

## Change

### Surface duplicates; never merge them

The instinct is to deduplicate — collapse the two cards into one. That is the
wrong move here, for a reason specific to this product: this app's thesis is that
a claim without evidence is worthless, and silently discarding a card the model
produced is the app making an unevidenced claim about the researcher's own work.
You cannot tell from two similar titles whether the second one is a
restatement or a real variation worth keeping, and the user can tell in a
second by looking.

So each card gains an **"Also extracted as"** line naming the near-duplicates and
linking to them, and the user decides. Nothing is merged, nothing is hidden, and
the decision to retire a card stays where invariant 4 puts every other decision —
with the researcher.

### Detection: character trigrams, calibrated rather than guessed

`app/dedupe.py` compares titles by **Jaccard similarity over character
trigrams**, after lowercasing and stripping punctuation. No embeddings, no extra
model call, no new dependency — and it is symmetric, cheap, and stable across
runs, which is what a UI hint needs to be.

Trigrams rather than word sets, because word-set similarity punishes exactly the
case that matters most: a reworded duplicate ("Selling sensors to hospitals" vs
"Sell sensors to hospitals") shares few whole words while sharing most of its
characters.

The threshold is set from measurement, not taste. On the pairs below, true
duplicates score **0.835 and up** while distinct ideas score **0.53 and down**:

| Pair | Score |
|---|---|
| identical after normalisation | 1.000 |
| case / punctuation only | 1.000 |
| one word changed in a 120-character title | 0.835 |
| a synonym swapped (`supplies` → `provides`) | 0.875 |
| the same idea with the words reordered | 0.892 |
| "…to small research groups at universities" vs "…to large pharmaceutical companies" | **0.530** |
| a marketplace in the same domain | 0.131 |

`NEAR_DUPLICATE_THRESHOLD = 0.60`. It sits **closer to the false ceiling than to
the true floor** on purpose: a chip that appears on two genuinely different ideas
is noise the user learns to ignore immediately, and then the feature is worthless
for everyone; a duplicate the feature misses costs the user one wasted glance.
Both errors are cheap, and they are not equally cheap.

The residual risk, stated: a paraphrase the model produces for the *same* idea
could land under 0.60 and go unflagged. Nothing here can fix that without
understanding the text, which is what an embedding model would be for. The
failure is benign — the user sees two cards, as they do today.

### Dismiss, and get it back

`"rejected"` becomes reachable: `POST /phase1/dismiss/{idea_id}`.

- **Only a `candidate` can be dismissed.** A card already selected into a venture
  is the thing a venture was built from; rejecting it would leave the venture
  pointing at an idea the account calls rejected. `kill_venture` moves a venture's
  idea back to `candidate`, and at that point it can be dismissed normally.
- **Dismissal is reversible**, because this app does not throw work away. The
  ideas page carries a collapsed list of dismissed cards with a restore button.
  One round trip to undo a misclick is not a safety net; somewhere you can look
  is.

`IDEA_STATUSES` needed no change and no migration — `"rejected"` was already in
the constants and already CHECK-constrained. Only the route and the page were
missing.

## Acceptance criteria

- [x] Two cards that are the same idea in different words both carry an "Also
      extracted as" line naming the other, on the dashboard and the ideas page.
- [x] Nothing is merged, hidden or deleted: both cards remain, and dismissing one
      leaves the other untouched.
- [x] Genuinely different ideas in the same domain are not flagged.
- [x] Dismiss and restore both work, and only for a card the researcher owns.
- [x] A card that is `selected` cannot be dismissed.
- [x] A dismissed card disappears from the candidates list and comes back on
      restore.
- [x] No model call: detection is arithmetic, so it costs no quota.
- [x] Works with JS disabled — every control is a plain form POST.
- [x] Tenant isolation holds: another user's idea is neither dismissible nor
      visible as a near-duplicate.

## Non-goals

- **No automatic merging, ever.** See above; this is the decision the slice is
  built around.
- **No embeddings and no second model call to judge similarity.** A model asked
  "are these the same idea?" costs a quota unit per comparison, can be wrong in a
  way that loses a card, and would make a *rendered page* depend on a model
  succeeding. Arithmetic cannot fail that way.
- **No comparing `commercial_framing`.** Titles alone are the signal. Framing
  text shares boilerplate between distinct ideas, which is exactly the kind of
  false positive above.
- **No bulk dismiss.** One card at a time, because each is a separate judgement.
