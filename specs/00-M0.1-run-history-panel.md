# M0.1 — Per-block run history panel renders

**Plan ref:** Adoption plan §2 / M0.1. One-word bug, one-word fix.
**Attacks:** nothing new — it removes a "this is a prototype" tell before anyone
outside the team sees the product.

## Problem

`_venture_context()` provides the per-block run history under the key
`focus_runs` (`app/main.py:481`). `venture_phase2.html` tests `runs` and loops
over `runs`, neither of which the context provides. Jinja's default undefined
renders as falsy, so `{% if runs %}` is simply always false: the "Runs on this
block" panel has never rendered. `focus_state` is computed for the same panel and
is likewise unused.

`db.list_segment_runs()` is correct, and the whole-venture "All runs" table below
the canvas works — so the data is there and only the template reference is wrong.

## Change

1. `app/templates/venture_phase2.html`: `{% if runs %}` → `{% if focus_runs %}`,
   `{% for r in runs %}` → `{% for r in focus_runs %}`.
2. Use `focus_state` in the same panel so the computed-but-unused context key has
   a purpose: a `resolved` / `at cap` marker next to the run count, read from
   `segment_run_state()` rather than recomputed in Jinja.
3. Add the block's hypothesis to the panel header (it is the thing every run on
   the block was testing, and it is currently only visible in the open panel).

## Acceptance criteria

- [x] Opening a block with ≥1 run shows "Runs on this block".
- [x] Each row shows the run number, the verdict (`decision`), the date the run
      was recorded, and whether it is scored / logged-not-scored / awaiting.
- [x] A block with no runs still renders the page with no history panel.
- [x] Regression test in `TestRendering` that fails against the old template.
- [x] Works with JS disabled (it is server-rendered markup, no JS involved).

## Non-goals

- Per-run hypothesis *text* is not stored on `cycles`; that arrives with M2.3
  (`criteria_sha256` / locked criteria). The panel shows the block's current
  hypothesis once, plus each run's first task title, which is per-run data that
  already exists in `todos_json`.
